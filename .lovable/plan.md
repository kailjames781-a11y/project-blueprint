# Zeruvo complete frontend

## Direction
Build the entire product as a **living engineering specification**: sharp ruled lines, numbered sections, editorial typography, status marks, and generous white space. No gradients, emojis, neon, or repetitive rounded SaaS cards.

## Public and account pages
- Build `/` around a live implementation plan excerpt, followed by the four numbered stages, simple credit pricing, direct registration and login actions, and a restrained footer.
- Build `/register`, `/login`, `/forgot-password`, and `/reset-password` with complete client-side validation and all requested success, waiting, expired-link, and security-safe error states.
- Build `/admin/login` as a visibly stricter administrative checkpoint within the same identity.

## Product shells
- Build a responsive user workspace for `/dashboard` and its profile, credits, subscription, payments, connections, download, and notifications pages.
- Build a responsive administration workspace for `/admin` and plans, users, payments, pricing, coupons, AI providers, connectors, notifications, and roles.
- Each placeholder page will clearly preserve navigation, page hierarchy, and sign-out placement while stating it will be built later.

## Frontend-only behavior
- Use local interface state to demonstrate form validation, success messages, access rejection, reset-link states, navigation, and sign-out.
- Do not add a backend, database, real authentication, persistent profiles, payment processing, or external connections.

## Quality
- Add unique English metadata to every content route.
- Ensure keyboard focus, form labels, mobile navigation, readable contrast, and responsive layouts.
- Verify the preview across desktop and mobile and resolve build or runtime errors.
